# 壁纸稳定性加固 2026-10-23

范围：current 2.0.1 源码。未构建、安装、发布或重启生产 Codex。用户重点是未来稳定，不是临时恢复当前窗口。

## 已核实问题

本机 2.0.0 在 13:27 和 20:25 重复出现样式已注入、documentHidden=true、视频未播放、native window unsupported。启动校验失败后停止服务并删除 state.json，监控随之禁用。视频大小和 SHA-256 正确。隐藏的上游原因尚未证实，不能直接归咎于应用更新。

已审阅启动、快速复用、注入守护、渲染器、视频恢复、多实例、还原及升级链路。现有页面重建修复、视频卡顿重试及端口身份校验予以保留。继续基于 MIT [Codex Dream Skin](https://github.com/Fei-Away/Codex-Dream-Skin) 的本地 1.5.18 引擎改造，没有自动升级上游。

## 改动

- 普通打开时，所有目标均为结构正确、版本/主题/修订匹配的隐藏页面，则保留服务并等待显示。不会强制激活窗口，也不宣称渲染成功。显式应用事务仍要求可见验证。
- 成功或等待显示的启动写入 recovery-intent.json，与临时 state.json 分开。会话缺失后监控继续重新发现并验证连接；新启动失败时也可重新启动监控。
- 恢复记录只提供用户意图和进程线索，不能证明进程或端口有效。保留进程启动时间、路径、端口归属和 BrowserId 校验。
- 主动还原外观也读取恢复记录清理服务，并清除恢复意图；取消保留。升级可结合恢复记录和监控身份清理已验证后台。
- 监控区分 waiting-for-codex、connection-required、monitoring，仅描述连接，不等同视频播放；暂无新增通知 UI。

## 验证

46 项 Node 测试和 17 次相关 Windows 脚本执行通过。包括实际监控控制流、隐藏启动循环、取消、还原、PID 重用、多窗口、快速启动、卸载及真实隔离进程升级。隐藏分类、恢复记录、仅有恢复记录的升级分别观察到修复前失败和修复后通过。

独立审查发现的还原/升级消费者遗漏已修复并复核。工作区根 `.local-evidence/stability-20261023/` 保存测试日志与原脚本备份。

## 剩余边界

这次修复不等于任何入口永不消失。普通无 CDP 的 Codex 无法无重启注入，现阶段记录 connection-required。监控尚无独立登录自启/自身崩溃监督；恢复记录损坏仍保守报错。原生首帧无闪白、宿主升级兼容性和真实休眠恢复未验证。

发布前需安装验收：冷启动、后台启动、最小化恢复、关窗重开、多窗口、休眠唤醒、视频服务退出、监控退出、升级、还原与取消。记录首次可见时间、恢复时间、空白持续时间和资源消耗。源码测试不能代替长期真实运行。
