# 启动弹窗与壁纸性能排查（2026-10-19）

接手来源：01a14a7e-396a-7f72-b4e2-b28fc16a9ba7。工作源码位于 `.tools/in-app-updates`，保留先前未提交的界面修改。本轮不发布、不上传。

## 已核实原因

- 本机安装目录 `LOCALAPPDATA/CodexDynamicSkin/logs` 中的重启记录显示：14:08 和 15:29 的 Codex 使用其他调试端口（2179、6581）；15:43、18:36 的主进程没有调试参数；17:05 从 `codex://threads/new` 启动。这些进程无法通过壁纸所记录的 9345 端口验证，所以触发重启确认。不能据此确定每次是谁启动了这些进程。
- `quick-launch.log` 反复出现本机 HTTP 请求超时。当前旧请求已能成功，无法复现当时超时，不能断言历史超时均由系统代理导致。
- 静态图片的完整启动快速恢复校验错误地要求视频进程、视频路径及视频命令参数，因此静态会话总是失去该快速路径。
- 壁纸应用的 ResultToken 原来禁用快速路径，导致完整启动重建服务。
- Windows 包激活明确返回 not-forwarded 时，旧代码仍等待调试端口最多 45 秒，没有立即采用已有的直接启动后备方案。

## 修复

- 本机 CDP HTTP 请求明确禁用代理、禁止重定向，并设置连接及读取超时；保留浏览器身份、页面及端口进程所有者校验。
- 静态会话仅校验注入进程；视频会话继续要求视频进程和内容身份匹配。
- 符合条件的壁纸应用复用服务，执行一次实际注入并验证新主题后写成功结果。失败继续进入完整恢复。静态与视频切换及视频内容改变仍走原恢复流程。
- 只有托管进程且连接尚未就绪时，在重启提示前短暂等待；真正未能验证的会话仍需用户确认重启。
- not-forwarded 立即转已有的备用启动方式，保留原有进程保护。
- 提示说明当前会话缺少壁纸连接，不再误导为每次都只需“重启一次”。
